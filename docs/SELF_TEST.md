# AI PMCoach｜复测反馈与防崩溃自测清单

测试入口：[本地首页](http://127.0.0.1:4192/#/)。以下按需求中的三组顺序排列，另列复测反馈与展示测试。

## 先准备

- 使用独立浏览器配置或无痕窗口，避免测试记录混入自己的真实成长历史。不要在日常使用窗口清空 localStorage。
- 完整测评仍为18道单选题。至少10道实际作答且测评完成才保存快照。正确率是主要成绩，雷达图与反馈用CAT能力估计。
- 情景题是新加的独立练习：结果页点击维度分数 →「重测这个维度」→ 完成3道专项题 →「练一道情景题」。也可直接打开 [AI基础情景练习](http://127.0.0.1:4192/#/scenario/1)。
- GitHub和公开网站默认不调用模型；本地版才有GPT。公开版本的情景题使用明确标注的基础规则评分，不能当作能力成绩。

## 复测反馈与雷达图

| 勾选 | 测试方法 | 应看到的结果 |
| --- | --- | --- |
| [ ] | 只完成一次完整测评，查看主页与结果页 | 只有本次轮廓，没有虚构的上次多边形；提示做完下次测评可看对比。 |
| [ ] | 比较两次CAT总分，第二次高10分或更多；可用下方 `celebrate` 测试数据 | 结果页顶部主色底白字卡片：「你在X天里提升了Y分！」日期间隔按实际完成时间算。没有撒花或数字跳动。 |
| [ ] | 总分提升不足10，但某维度提升至少15；可用 `breakthrough` 数据 | 显示具体维度突破卡片、提升分数；可以与持平提示并存，不忽略单项进步。 |
| [ ] | 第二次总分下降；可用 `decline` 数据 | 橙色建设性反馈，含「今天的表现可能不在最佳状态」及回顾建议。「查看本次错题」能展开本次错误和跳过的题、用户选项、最佳答案与解析。 |
| [ ] | 总分不下降且变化在0—5分内；可用 `stable` 数据 | 温和说明表现稳定，点名本次最低分维度，并建议专项练习。没有承诺下次必然提高。 |
| [ ] | 总分提高6—9分 | 如实说明提升几分，不套用10分庆祝。自动测试覆盖此区间。 |
| [ ] | 观察最近两次叠加雷达图 | 本次实线、主色填充约0.3；上次浅灰虚线、无填充；两条边线均2px，标签字号统一。提升绿色，下降橙色。 |
| [ ] | 连续完成三次测评，点击完整成长曲线 | 时间轴每次测评只有一个节点；六维度趋势可分别开关；刷新不重复保存快照。 |

说明：下降反馈优先于「变化5分以内」稳定反馈，例如下降1分也使用建设性下降话术。总分庆祝与单项突破可以同时显示。

## 第一组：核心边界

| 勾选 | 测试方法 | 应看到的结果 |
| --- | --- | --- |

| [ ] | 模拟API返回空文本、JSON或无关格式 | 同样重试后降级；不把原始异常文本当报告展示。 |
| [ ] | 在本地打开 `http://127.0.0.1:4192/?qa-bank=empty#/intro`，点开始 | 不启动测评，显示「题库未就绪，请联系管理员」。此开关仅限开发预览，不改变真实题库。 |

| [ ] | 做3题，第4题选一个选项，关闭窗口；重新进入同一浏览器配置的主页或介绍页 | 明显卡片：「你有一次未完成的测评，继续作答？」附已完成题数及「继续」「放弃重来」。 |
| [ ] | 点击「继续」，刷新后再继续 | 恢复相同题号、选项、CAT难度和进度；每次完成一题马上保存。关闭浏览器期间不计入完整测评用时。 |

| [ ] | 在全新的无痕窗口直接进入 `#/results` | 显示「完成测评后查看你的能力雷达图」与开始入口，没有空雷达图。未完成记录则提供继续答题。 |
| [ ] | 情景题粘贴1800字，再粘贴2001字；含表情也可测试 | 接近上限显示「还可以写X字」；超出强制截到2000个字符，提示「请控制在2000字以内」。完整粘贴可检验截断，不仅依赖浏览器maxLength。 |
| [ ] | 情景题输入空白、仅空格、19字，再输入20字 | 前三种出现「回答太短，请详细描述你的想法」，提交按钮不可点；20字起允许提交。首尾空格不算有效内容长度。 |
| [ ] | 情景题快速连点提交，或反复按回车 | 点击立即显示「提交中...」，输入和提交禁用，同一回答只发一个评分任务，请求结束后恢复。选择题的下一题、跳过和最后提交也有提交锁。 |

| [ ] | 浏览器存储不可用或满额 | 页面继续可用，显示记录保存提醒；不能声称已保存。诊断/资源可在当前页面使用，刷新不保证恢复。自动测试使用会抛出异常的存储模拟器。 |

## 第二组：AI失控时的产品响应

| 勾选 | 测试方法 | 应看到的结果 |
| --- | --- | --- |
| [ ] | 提交一份20—2000字情景题回答 | 除总分外，展示思路清晰度、关键点覆盖、实操可执行性、风险与验证四项，每项满分25、独立得分与依据。总分由代码相加。 |
| [ ] | 查看本地AI评分的依据 | 每项引用用户原回答里的连续原话；不是用户写过的引语、越界分数、缺项或错误格式会被拒收，重试后降级。基础评分会说明仅匹配表述，不冒充语义评分。 |
| [ ] | 点击「我觉得评分不准」，填写理由保存，刷新 | 显示反馈已保存，localStorage键 `ai-pmcoach-appeals-v1` 有理由、日期、维度、回答和评分；同一提交不重复存。提示「你的反馈会用于改进评分模型」。当前仅本地保存，没有上传，也不会自动改分。 |
| [ ] | 申诉为空，或存储写入失败 | 空理由无法提交；保存失败显示明确提醒，可重试，不显示虚假的成功。 |

## 第三组：主动规避

- [ ] 主页、结果、成长曲线、专项与情景页都不出现连续打卡天数。
- [ ] 没有积分商城或兑换入口。
- [ ] 没有PK排行榜、用户排名或竞争提示。
- [ ] 没有每天必须来、每天必须完成任务等强制激励。复测提醒可以提前点击，不禁止测评。

本次检查原产品不存在上述四类功能，因此没有需要删除的功能。

## 辅助：准备可重复的反馈测试数据

不必反复做18题来触发全部反馈。项目中提供纯模拟测试数据生成器，结果与公式一致，文件只写入被Git忽略的 `.sites-local`，不会发布或上传。

在项目终端运行：

```powershell
node scripts/make-self-test-fixtures.mjs
```

在独立/无痕窗口打开本地介绍页。浏览器开发者工具的Console运行下面一次性辅助程序（**仅在测试窗口使用**）：

```js
const qaFixtures = await (await fetch('/.sites-local/self-test-fixtures.json')).json();
window.qaLoad = async name => {
  location.hash = '/intro';
  await new Promise(resolve => setTimeout(resolve, 50));
  for (const key of Object.keys(localStorage)) {
    if (key.startsWith('ai-pmcoach-ai-v2-')) localStorage.removeItem(key);
  }
  for (const [key, value] of Object.entries(qaFixtures[name])) {
    localStorage.setItem(key, JSON.stringify(value));
  }
  location.hash = '/results';
};
```

再执行 `await qaLoad('celebrate')`、`await qaLoad('breakthrough')`、`await qaLoad('decline')`、`await qaLoad('stable')`、`await qaLoad('one')` 或 `await qaLoad('insufficient')`。不要在真实用户窗口使用这些数据。

## 辅助：模拟模型失败与无题号输出

先停在介绍页，避免诊断已自动生成；上述辅助程序会移除测试窗口中的诊断缓存。在Console保存原fetch并设置失败模拟：

```js
window.qaOriginalFetch = window.fetch.bind(window);
window.qaCalls = 0;
window.fetch = async (url, options) => {
  if (String(url).startsWith('/api/') && options?.method === 'POST') {
    window.qaCalls++;
    console.log('模拟模型失败', window.qaCalls, new Date().toISOString());
    return new Response('{}', {status: 429});
  }
  return window.qaOriginalFetch(url, options);
};
await qaLoad('celebrate');
```

观察第一次、第二次、第三次时间差分别约1秒、3秒，加上请求耗时。只自动生成最弱维度，因此未展开其他维度时应为3次。展开其他维度会有各自的重试。

无题号测试：将模拟返回改为200及如下包装；从介绍页重新加载未缓存测试记录。

```js
return new Response(JSON.stringify({text:
  '一句话总结：本次判断需复核\n' +
  '具体问题：需要核对题干约束\n' +
  '可能原因：可能遗漏限制，待验证\n' +
  '下一步行动：写出方案对照表，完成标准：逐项对应题干条件\n' +
  '正向鼓励：先完成一次有明确依据的练习'
}), {status: 200, headers: {'Content-Type': 'application/json'}});
```

测试完执行 `window.fetch = window.qaOriginalFetch`，或关闭这个无痕窗口。不要记录、复制或发布 `/api/ai-status` 返回的临时会话值。

## 本次自动验证

- `node --test tests/*.test.js`：核心算法、持久化、重试、诊断证据、情景输入长度、评分依据、申诉、专项练习与重复提交锁。
- 页面渲染检查：庆祝、突破、下降、稳定、单快照、数据不足、无数据、题库拦截、短情景回答与分数说明。
- `npm run build`：生产构建。
- 本地GPT用模拟情景回答进行真实接口验证，真实结果仍应由你按此清单做交互验收。
